# 聊迹 · Chat Scribe

[English](README.en.md) · 简体中文

将 iPhone 微信截图整理成可编辑文档的原生 Mac 应用。SwiftUI + AppKit 界面，Apple Vision 本机文字识别，无第三方依赖、服务器、账号或 API 密钥。

当前版本 1.6：支持简体中文、繁體中文、日本語、English、한국어界面；增加带实际图片附件的 Markdown、阅读收藏版 Word 和 AI 分析版 Word。保留素材夹、快速核对与深色模式，图文导出移到后台执行。

## 启动

双击 `dist/聊迹.app`。需要 macOS 14 或更新版本；当前提供的构建适用于 Apple Silicon Mac。可以将应用拖入“应用程序”文件夹。

当前应用为本地临时签名，未经过 Apple 公证。若把压缩包复制到另一台 Mac，系统可能要求通过“右键 → 打开”允许首次启动。

## 使用

1. **导入**：从 Mac“照片”App 或访达直接拖入一张或多张截图，也可按 **⌘I** 选择文件，或按 **⇧⌘V** 粘贴已复制的截图。支持 PNG、JPG、HEIC、TIFF；单文件最多 30 MB。
2. **校对**：左边看截图，右边直接改文字；点击消息会高亮并滚动到对应原图。点击“快速核对”可逐条放大原文，改好后按 **⌘↩** 确认并继续。点击说话人可修改归属。右键左侧缩略图可以调整先后顺序。
3. **导出**：点击右上角“导出文档”，选择“Word · 阅读收藏”“Word · AI 分析”“Markdown · 图文与上下文”或 PDF。导出包含所有未排除的消息，不受搜索筛选影响。

### 软件语言

在“更多 → Language / 语言”或“文档设置 → 界面语言”中选择简体中文、繁體中文、日本語、English、한국어，立即生效并记住选择。仅改变界面和导出说明文字，不翻译或修改聊天原文、署名与已有标题。系统文件对话框的部分按钮沿用 macOS 的语言。

本机 OCR 按系统支持的语言启用简体、繁体、英语、日语和韩语，并自动检测文字语言。界面语言与聊天内容的语言可以不同。

### 保存、回看与 AI 分析

- **Word · 阅读收藏**：清晰的标题、参与人、按顺序编号的消息、时间标签、核对状态、截图来源与实际图片。使用 Word 标题样式，方便导航、检索和回看。
- **Word · AI 分析**：保留完整图文记录，补充最近的时间标签，并附可编辑的分析目标与提示。提示要求引用消息编号、区分事实与推测、指出缺失信息，给出不同语气的回复建议。它是供 AI 阅读的材料，不是已经完成的分析，也不会自动发送给任何 AI 服务。
- **Markdown · 图文与上下文**：保存 `.md` 文件，并在同目录建立唯一命名的 `Liaoji-assets-…` 图片文件夹。用相对链接显示裁切图片；拷贝、移动或交给 AI 时，请一起携带该文件夹。覆盖 Markdown 时会生成新附件目录，避免破坏其他副本正在引用的旧图片。
- 消息原文在 Markdown 中作为引用内容保存，与文档说明和分析提示分开；消息编号只表示本次导出顺序，不是微信原始消息 ID。排除的消息不会导出；“待人工核对”提醒可能存在 OCR 错误。
- 导出在后台进行。开始后会固定本次导出的内容与语言，失败时恢复编辑状态。生成文件不需要网络、账号或 API 密钥。

### 图片与表情

1. 选择左侧截图，点击“框选素材”（⇧⌘M），在原图上拖出图片或表情区域。可以放大截图，也可展开“精细调整选区”微调四边。
2. 查看保存预览，选择图片/表情包及发送者，按需填写说明和关键词。点击保存后，素材按原图中的位置插入聊天记录，前后文字继续保留。
3. 若选区完全包含 OCR 消息，可主动勾选排除这些文字，避免图片内的字被重复导出。默认保留原文字；保存、排除及说明修改均可撤销。
4. 右侧“素材夹”按图片/表情包、收藏和关键词筛选。可修改分类、说明、关键词及发送者，点击“回到原图与上下文”返回对话。相同归一化缩略图会提示可能重复，保留每次发送记录，不自动删除。
5. “导出素材”将当前筛选结果保存到新文件夹，包含静态 PNG 和可阅读的 Markdown 目录；单项也能导出。排除的素材不计入素材夹，可在文字界面“显示已排除消息”后恢复。

Word/PDF 嵌入图片；Markdown 通过同目录的附件显示图片。TXT 和复制文字保留素材类型与说明。素材通过原截图及裁切位置保存，完整项目不依赖外部图片路径。截图重试 OCR 会保留素材；移除截图会同时移除关联素材，可以撤销。

重新识别时，保留素材内原位置、相同初次识别文字的排除状态，避免已排除的图片内部文字重新出现在文档中。内容改变、位置不同或仅部分落在素材内的文字会保留供核对，不自动排除。接近项目容量上限时，会将保留素材一起计入；超限则保持原项目不变。

截图中只能取得静态画面，不能恢复 GIF 动画、原文件分辨率或截图外的内容。素材由用户框选，不自动猜测图片、表情或头像。每个项目最多 500 份素材；图文文档的图片数据限 80 MB、处理后总像素限 4000 万，以控制导出内存；素材文件夹导出限 300 MB。添加素材后项目格式升级，需要聊迹 1.5 或更新版本编辑；旧版文字项目可直接打开。

界面采用两栏，核对进度和确认操作只在“快速核对”中显示；设置仍收在“更多”中。

- **快速核对**：点击文字区右上角按钮，或按 **⇧⌘R**。原图局部支持 100%–300% 放大；**⌘[ / ⌘]** 切换待核对消息，跳过不会自动确认。消息菜单也可以直接核对或重新核对某一条。
- **需留意**：优先查看低置信度、数字/时间、未识别字符、可能重复、空白或缺少原图区域的消息。提示用于辅助检查，不能判断文字一定正确；请以原图为准。修正提示后当前消息会留在屏幕上，直到确认或切换。
- **局部重新识别**：仅识别当前原图区域，先预览结果，点击“采用此结果”才替换文字；切换消息或手动修改后丢弃迟到结果。可展开查看初次识别文字，旧项目则从原图 OCR 区域还原供参考。
- **核对进度**：人工确认随项目保存，重启后仍在。修改已确认的文字、说话人或单条署名会恢复待核对；确认、排除、采用识别结果均可撤销。空白消息需要补充或排除，导出会跳过空白消息。

- **外观**：右上角“更多 → 外观”可选择“跟随系统 / 浅色 / 深色护眼”，文档设置中也有切换入口。应用记住选择，重启后保留。深色模式使用柔和深灰背景，原始截图及导出的 Word/PDF 不会被改色；界面内文档预览随主题变化。

- **撤销与重做**：⌘Z 撤销、⇧⌘Z 重做，支持修改文字、修改称呼、移除截图、排除重复、合并、拆分和整批导入。连续输入会合并为一步。最近 30 步在当前打开项目内有效；新建、打开或重启后清空历史。
- **截图排序**：直接把缩略图拖到另一张缩略图上，文字顺序会一起调整。排序也可以撤销。
- **停止导入**：从照片接收期间可取消等待；批量 OCR 中点击“停止”会完成当前截图，并停止后续图片。已成功导入的内容保留。重复图片会跳过，底部显示结果。
- **搜索**：⌘F 打开搜索，点击叉号关闭。标准 ⌘V 继续用于编辑文字，⇧⌘V 专门用于导入图片。
- 原图、素材和缩略图使用有容量限制的缓存；原图按实际像素内存估算，避免压缩文件很小却占用大量解码内存。

- 标题可直接在文字上方修改。双方称呼、文档说明和截图识别范围收进右上角“更多 → 文档设置”；识别范围默认折叠。重新识别会替换当前截图的手动修改，操作前会确认。
- 消息菜单保留修改署名、合并、拆分、排除。群聊可为单条消息填写署名。误排除的消息可从“更多 → 显示已排除消息”恢复。
- 不同署名的群聊消息不会合并为同一条，也不会被当作截图重叠候选；拆分已排除消息时保留其排除状态。
- 疑似截图重叠内容会保留并标记，确认后可点击“排除重复”。
- 自动保存继续有效。**⌘S** 可另存含截图的 `.liaoji` 完整项目，**⌘O** 重新打开。升级兼容旧项目。
- 示例项目移到系统“Help → 打开示例项目”，内容完全虚构。

照片 App 的拖入优先接收系统文件承诺，再处理文件 URL 或直接图片数据；无需先将图片导出到访达，也不会读取整个照片图库。接收多图时保留拖入顺序；访达文件按名称自然排序。收到的图片保存副本，临时接收文件会清理。

## 数据与限制

- 自动保存位置：`~/Library/Application Support/Liaoji/workspace.liaoji`。原子保存，`.previous` 保留上一次内容不同的有效版本；未修改时退出或再次保存不会覆盖它。主文件或其截图损坏时尝试恢复有效备份，损坏原文件先复制到 `Recovery/`。两份都无法读取时暂停写入；新建或打开其他项目会先保护原文件，再恢复正常保存。
- 新建或打开另一个项目时，当前有内容的项目会保存到同目录下的 `Archives/`，以防丢失。菜单“整理 → 打开本机数据与归档”可以找到它们。归档可通过“打开项目”恢复。
- 导入后保存规范化的图片副本，不依赖原始路径；图片最长边超过 3600 像素时缩小到 3600，HEIC 自动处理方向。项目最多 300 张截图、图片总量 300 MB。
- 文件保存在本机，**未加密**。完整项目包含原图，导出文件包含聊天内容，请自行选择可信的存储位置。
- 主要适合清晰的双人文字聊天截图，支持简体中文、繁体中文、英文。OCR 和气泡识别属于启发式处理，不能保证完全准确；截图顺序需要用户核对，不能仅凭日期自动还原跨天的完整时间线。
- 群聊昵称、连续短消息、深色主题、图片中的文字、引用、转账卡片、链接卡片等可能被拆错或识别成普通文字，需要校对和补充。图片/表情可手工框选保存，不会自动解释含义；不能转写语音或恢复已删除的聊天。这也不是微信数据库导出工具。
- 重叠检测仅标记相邻截图中至少两条、总计至少八个规范化字符的完全一致连续文字，不会模糊匹配或自动删除。OCR 识别有差异时可能漏标；时间/系统记录不参与重叠检测。
- 重叠比较保留标点和大小写，避免把 `123.45` 与 `12345`、大小写不同的文字当作相同内容。排除原消息后会刷新标记，批量排除前再检查一次，保留仍需导出的副本。
- 文档预览展示内容与大致样式；Word 和 PDF 使用适合文档的纵向排版，具体换行和分页以导出文件为准。

## 从源码构建

安装 Apple Command Line Tools 后执行：

```bash
./scripts/build-app.sh
open dist/聊迹.app
```

脚本构建本机架构的 `.app`，并生成 ZIP 压缩包。无需完整 Xcode。也可运行：

```bash
./scripts/swift.sh build
./scripts/swift.sh run CoreChecks
./scripts/swift.sh run ChatScribe --self-test --output /tmp/Liaoji-Checks
```

核心检查覆盖解析、重叠检测、项目往返、撤销、核对队列、初次识别基线与空白过滤，以及备份恢复、文字顺序、素材插入位置、旧格式兼容和重新识别的保守排除逻辑等。集成检查使用独立工作区，验证素材裁切与保存、Word/PDF 实际图片、核对截图切换与移除联动、导入后的显示状态、接近 50000 条消息的容量拒绝及保存恢复，以及现有 OCR、撤销和深浅配色。文件承诺测试使用受控接收器，测试运行不会加载当前真实工作区。

多语言检查覆盖全部翻译键及占位符、语言切换时的数据不变、状态文字重新显示、五种语言的 Word、真实 Markdown 图片链接、异步导出的语言快照与失败清理。

## 源码与隐私

仓库只包含源码、图标、构建脚本和生成虚构示例的测试代码。`.liaoji` 项目、截图、自动保存、备份、验证输出、构建产物与凭据文件不应提交。发现问题时，请提供虚构或脱敏后的最小示例，不要直接上传私人聊天记录。

参与开发请见 [CONTRIBUTING.md](CONTRIBUTING.md)。应用没有遥测，也不调用远程 AI。

可用环境变量 `LIAOJI_DATA_DIR` 指定独立数据目录，适合测试。

实现参考：[Apple Vision 文字识别](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)、[Apple AppKit 文件承诺拖放](https://developer.apple.com/documentation/appkit/supporting-drag-and-drop-through-file-promises)。
